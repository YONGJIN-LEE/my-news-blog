## 2. 원인 (영향이 큰 순서)

### ① 발행량이 86% 줄었다 (하루 51개 → 7개)
뉴스 블로그 유입은 대부분 "그날 검색량이 튀는 키워드"에서 온다. 글 하나가 트래픽을 받는 기간은 보통 1~3일이다.
따라서 **방문자 수는 그날 발행한 글 수에 거의 비례**한다. 4월에 비해 지금은 검색 결과에 걸 수 있는 키워드 수 자체가 1/7이다.
"올해 초엔 훨씬 많았다"는 체감은 이것 하나로도 대부분 설명된다.

### ② 같은 글이 여러 곳에 동시에 올라간다 (Blogger · 네이버 · 이 사이트)
`publish_to_blog.py`는 Blogger 파이프라인과 **같은 초안(drafts/published)** 을 읽고, SETUP_GUIDE의 흐름은 네이버 블로그에도 그대로 붙여넣는 방식이다.
검색엔진은 같은 글이 여러 곳에 있으면 한 곳만 남기고 나머지는 결과에서 뺀다. 이때 오래되고 신뢰가 쌓인 도메인(Blogger, 네이버)이 원본으로 뽑힐 가능성이 높아
`*.pages.dev`의 이 사이트는 밀려난다. (SETUP_GUIDE 체크리스트의 "canonical 대상 1곳 지정"도 아직 미완료)

### ③ "대량 AI 뉴스 재가공" 사이트로 평가될 위험
4월에 하루 50개 이상을 올렸고, 원문 출처 링크 없이 기존 보도를 재구성한 글이 대부분이다. 구글은 2024년 3월부터
"대량 생산 콘텐츠(scaled content abuse)"를 스팸 정책으로 다루고, 이후 코어 업데이트에서도 이런 사이트의 순위를 사이트 단위로 낮춰 왔다.
4~5월에 대량 발행한 뒤 유입이 계속 줄어든 흐름은 이 패턴과 맞는다. **추정**이므로 Search Console의 색인 수와 노출수 추이로 확인해야 한다.

### ④ 엉뚱한 이미지 + 남의 이미지 핫링크
본문 이미지의 63~87%가 **몇 년 전 기사 사진**이다(예: 2026년 AI 해킹 글에 2018년 블록체인 기사 사진).
네이버 이미지 검색 결과를 그대로 붙이는 구조라서 생기는 문제다. 결과적으로
- 구글 디스커버·이미지 검색 노출이 어렵고(디스커버는 큰 고품질 이미지가 필요)
- 언론사 이미지 저작권 문제가 생길 수 있으며
- 독자가 보기에 신뢰도가 떨어진다.

### ⑤ 검색 결과 클릭률을 깎는 기술적 문제 (이번에 코드로 수정함)
| 문제 | 영향 |
|---|---|
| 메타 설명 = 제목 | 검색 결과 스니펫이 제목 반복이라 클릭할 이유가 없음 |
| 내부 링크 0개 | 방문자가 1페이지만 보고 이탈, 크롤러가 오래된 글을 찾지 못함 |
| sitemap `lastmod`가 매 빌드 시각(4천 개 URL 모두 동일) | 구글이 lastmod 값을 무시하게 됨 → 새 글 발견이 느려짐 |
| `max-image-preview:large` 없음 | 디스커버/검색 결과에 큰 썸네일이 노출되지 않음 |
| 사건사고·미분류 글 280여 개가 어떤 목록에서도 링크되지 않음 | 크롤링·색인 누락 |
| 같은 이슈 반복 게시 (예: `손흥민세대교체론`/`손흥민세대교체`, `갤럭시버즈온`/`갤럭시버즈온후기`) | 내 글끼리 같은 키워드를 두고 경쟁 |

### ⑥ 분야 구성: 가장 경쟁이 센 분야에 몰려 있다
IT 24%, 스포츠 21%, 패션 16%, 정치 10%. 모두 언론사·포털이 1분 안에 기사를 내는 분야다.
개인 사이트가 같은 속보 키워드로 언론사를 이길 방법은 거의 없다. 패션 글은 대부분 쇼핑몰·잡지 보도자료를 다시 쓴 것이라 검색 수요 대비 경쟁이 특히 심하다.

## 4. 저장소 밖에서 해야 할 일 (우선순위)

### P0 — 이번 주
1. **배포할 곳을 하나로 정하기.** 이 사이트를 키울 생각이라면 Blogger에는 같은 글을 올리지 않거나, Blogger 글에 이 사이트 원문으로 가는 canonical을 걸어야 한다. 네이버 블로그는 원문 전체를 붙이지 말고 요약 3~5줄과 원문 링크만 올린다.
2. **Search Console + 네이버 서치어드바이저 확인.** `GOOGLE_SITE_VERIFICATION`, `NAVER_SITE_VERIFICATION`, `GA4_ID` 환경변수가 빌드에 들어가고 있는지, sitemap이 제출돼 있는지 확인한다. (코드상 값이 없으면 태그가 출력되지 않는다)
3. **커스텀 도메인 연결.** `*.pages.dev`는 신뢰 신호가 약하다. 연 1~2만 원 수준이고, 도메인을 바꿀 때는 301 리다이렉트를 꼭 건다.

### P1 — 초안 생성 프롬프트 수정 (아래 5장 템플릿)
4. 하루 발행량은 **5~8개를 유지하되** 각 글이 "기사 재요약"이 아니라 정보를 하나 더 얹도록 한다(정리표, 일정, 체크리스트, 비교, 의미 해설).
5. **원문 출처 링크를 본문 끝에 2개 이상** 넣는다. 소개 페이지의 편집 방침과 실제 글이 일치해야 신뢰 평가에서 불리하지 않다.
6. **이미지 정책 변경**: 기사 날짜와 2년 넘게 차이 나는 언론사 사진은 쓰지 않는다. 공식 보도자료 이미지, 직접 만든 정리 이미지(표·인포그래픽), 무료 라이선스 이미지(Unsplash 등)를 우선한다.

### P2 — 1~3개월
7. 분야 재편 (6장).
8. 조회가 나오는 글은 다시 쓰지 말고 **기존 글을 업데이트**(본문 상단에 "업데이트: 날짜" + `lastmod` 갱신)해서 신호를 한 URL에 모은다.
9. 오래된 저품질 글 정리: 노출 0인 4~5월 글(특히 출처 없이 짧은 글)은 보강하거나 `draft: true`로 내린다. 저품질 글이 많으면 사이트 전체 평가가 내려간다.

## 5. 초안 생성 프롬프트에 넣을 규칙 (그대로 복사해 사용)

```
[글쓰기 규칙]
1. 제목: "핵심 키워드 + 독자가 얻는 것" 형태, 32자 이내. 자극적 표현(충격/경악/결국/난리) 금지.
   예) "김하성 퀄리파잉 오퍼 불발, FA 시장 영향 3가지"
2. 첫 문단(2~3문장): 무슨 일인지 + 왜 중요한지를 바로 쓴다. 이 문단이 검색 결과 설명으로 쓰인다(150자 안팎).
3. 본문에 기사에 없는 정보를 최소 1개 넣는다:
   - 일정/숫자 정리표, 이전 사례 비교, 독자가 할 일 체크리스트, 용어 설명 중 하나 이상
4. 소제목(##)은 3~4개, 실제 검색어처럼 쓴다. ("왜 중요한가" 같은 일반 소제목 금지)
5. 확인되지 않은 내용은 "~로 알려졌다", "공식 발표는 없다"로 명확히 구분한다.
6. 마지막에 아래 형식의 출처 섹션을 반드시 넣는다:
   ## 출처
   - [매체명 기사 제목](원문 URL)
   - [기관명 보도자료](원문 URL)
7. 같은 이슈를 7일 안에 다시 다룰 때는 새 글을 만들지 말고 "업데이트"로 표시해 기존 글을 보강한다.
8. 태그는 6~10개. 고유명사 중심, '오늘이슈/뉴스정리' 같은 범용 태그 금지.
```

## 7. 검증 방법 (Search Console에서)

1. **실적 → 날짜 범위 16개월 → 노출수 그래프**: 하락이 발행량 감소와 같이 서서히 줄었는지(①), 특정 날짜에 계단식으로 떨어졌는지(③, 코어 업데이트 날짜와 비교) 확인
2. **페이지 색인 생성 → "발견됨 - 현재 색인이 생성되지 않음 / 크롤링됨 - 현재 색인이 생성되지 않음"** 수가 수천 개라면 ③ 가능성이 높음
3. **URL 검사**로 최근 글 하나를 넣고 "Google에서 선택한 표준 URL"이 Blogger 주소로 나오면 ②가 확정
4. 이번 수정 배포 후 2~4주 동안 **평균 CTR**(메타 설명 개선 효과)과 **페이지/세션**(관련 글 효과)을 GA4에서 비교
